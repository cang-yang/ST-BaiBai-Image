# 正文配图预设

这是柏宝绘自己的提示词预设库，不是工作流库，也不是对智绘姬全部任务档案的复制。
提示词只有一个设置入口：**设置 → 正文配图预设**。原“自定义提示词”和漫画的创作规范已合并到这里；API、工作流节点参数与漫画版式仍在各自页面。

设置按任务分为“生成设置”“参考与过滤”“界面与存储”，切换分类不会销毁未保存的预设草稿。
生成设置集中展示当前预设、提示词 API 与自动生成状态。原“副 API”入口改名为“提示词 API”，请求逻辑与凭证不变。
漫画版式默认只展示可选名单与用途，“允许选用”不是轮换顺序或固定版式；逐项编辑、批量画布与旧版说明按需展开。

## 日常使用

1. 点击“新建”，或选中已有预设点击“编辑”。内置默认需先“复制并编辑”。
2. 点击“使用此预设”。切换只影响下一次图片提示词请求，不影响主 API 续写正文。
3. 需要分享时导出 JSON；导入后先检查，再手动启用。导入不会覆盖同名预设。
4. 想恢复插件默认规则，选择“内置默认”并点击“使用此预设”。想恢复升级前的自定义内容，选择“原有提示词（已迁移）”。

编辑器直接使用下方四个分类，不再重复展示内容目录。“画面要求”中的条目选择列表跟随插件主题，支持长名称换行、选中标记和键盘选择；停用条目保留“停用”标记，搜索仍可按名称或内容筛选。

编辑区域分为四个页签：

- **画面要求**：内容、风格、示例与条件条目；漫画场景的文字要求与叙事表现也在这里。
- **规范与检查**：优先显示当前场景的规范与检查指导；其他后端规则在折叠区内保留。每项可选“内置参考”“本预设自定义”或“不附加”。
- **输出与变量**：工具输出、工作流提示词格式、漫画文字要求、通用前置规则与局部变量。
- **外部附加**：只读查看当前版式清单与来源；本地检查后可查看本次固定协议及完整实际请求。

预设列表下方显示当前或所选预设的规则来源；未启用的选择和未保存的草稿都有明确标记。
每份预设独立保存规则，不再实时继承另一处全局自定义文本。内置参考随插件更新；需要固定文本时切为“本预设自定义”。

每份预设可以新增、停用、排序和编辑条目，条目有 system/user/assistant 三种消息角色。
从 0.3.21 起，条目的“插入位置、条件与角色”中可以选择：

- **资料前 · 任务约定**：默认位置，适合任务边界、要求与示例。旧预设保持此位置。
- **资料后 · 执行与核对**：放在实际正文、参考资料及生图世界书之后，适合核对、执行和收束要求。列表用“资料后”标记。

实际顺序是资料前条目 → 插件协议与参考资料 → 资料后条目 → 本次提交方式。各组内部按条目顺序执行；局部变量也按该顺序赋值和读取。跨组移动条目的上下顺序不会改变其插入位置。资料后条目不改变世界书相对于原正文资料段的深度位置。
包含资料后条目的预设导出为 v3 格式，需要 0.3.21 或更新插件；普通预设仍导出为 v2，旧 v1/v2 均可导入。

条件条目匹配**本次携带的此前上下文与目标正文**。关键词用英文逗号、中文逗号或换行分隔，区分英文大小写，按普通子串匹配；第一组任一词命中后，填写了第二组时还须命中第二组任一词。不是正则，也不冒充酒馆世界书扫描规则。需要酒馆完整触发逻辑时使用“生图世界书”。

预设只写画面偏好与提示词要求即可。插件自动附加：

- 目标正文和有效的 P 位置、上下文、角色卡、人设、角色固定外貌库和可用记忆。
- 已触发的世界书，包括独立生图世界书，仍按原来的位置与深度注入。
- 当前图片数量、画幅方向和输出协议。
- 本预设选用的规范与检查指导；设置为“不附加”即不发送该项。**漫画 Layout 的坐标与输出结构约束仍保留**，避免无效格式。

新建预设默认不附加通用前置规则；“内置默认”保留插件原有内置前缀，可以复制后自行关闭。
预设不能改变最终的图片插入协议；自由度用于内容、风格与组织消息，不用于绕开数据验证。

## 升级与漫画配置

首次升级会把旧全局自定义提示词、漫画规范与检查指导保存为“原有提示词（已迁移）”。原先没有启用自定义预设时，自动使用此迁移预设；原先已经启用预设时，保持选择，并把其原来继承的规则固化在该预设内。重复加载不会重复迁移。
旧字段仅作数据备份，之后修改预设不会再读写这些全局文本。

RunningHub 的“应用漫画配置”会把工作流附带的漫画规范存为一份新命名预设并启用，保留原预设。漫画版式编辑器只管理几何、画布和版式说明，不再管理创作提示词。
这些规则只进入图片提示词请求，不写入主 API 的正文生成配置。

## 内容变量

正文等数据自动随请求发送，通常无需手动插入变量。需要在特定条目中引用时可以使用：

已启用且命中的条目通过内置变量实际引用了某份非空资料后，插件不再自动附加该资料的第二份。停用、未命中、空值以及被自定义变量覆盖的同名变量不会让真实资料丢失。预设自身故意重复引用不做删改；独立生图世界书仍按自身规则注入，不受 `worldbook` 变量去重影响。

| 变量 | 内容 |
| --- | --- |
| `{{story}}` | 带 P 编号的目标正文 |
| `{{context}}` | 本次携带的此前上下文 |
| `{{character}}` / `{{persona}}` | 角色卡 / 用户人设 |
| `{{worldbook}}` | 原全局世界书路径取得的文本；独立生图世界书仍按自己的规则注入 |
| `{{library}}` / `{{memory}}` | 角色固定外貌库 / 柏宝书记忆 |
| `{{task}}` | 单图重写等本次任务备注 |
| `{{user}}` / `{{char}}` | 用户 / 角色名字 |
| `{{min_images}}` / `{{max_images}}` | 本次要求的图片数量范围 |

在“输出与变量”中添加自己的名称与文本后，用 `{{名称}}` 引用。也支持顺序执行的局部文本赋值 `{@setvar::名称::文本@}`、读取 `{@getvar::名称@}`，以及 `{{roll 6}}`。
变量只在本次请求中存在，不读写酒馆聊天变量或全局变量。替换进去的正文和变量值不会再次当作代码或宏执行。
未提供的变量会阻止请求，并列出名字，不会悄悄替换为空串。

## 工具输出、流式与直连

“普通文本”让模型返回 JSON；“工具输出”使用唯一的数据工具 `submit_image_plan`，其参数就是同样的配图 JSON。
工具不能执行命令、读取文件或自行调用生图后端。只有完整输出通过位置、数量与字段校验后才进入原有配图流程。
未知工具、多个调用、损坏的参数、被截断的输出均报错，不使用半截内容生成图片。

工具模式需要**独立副 API 渠道和支持 OpenAI 兼容 tools 的模型/服务**。不支持时请改回普通文本，不会自动重复发送另一种请求。
工具选择使用 `tool_choice: auto`，不强制指定函数，避免部分思考模型拒绝请求。宿主提示词仍要求提交唯一的配图工具；普通文字、未知工具或多个调用不会当作成功，也不会自动关闭思考模式或更换模型。
渠道原有“流式传输”开关对普通文本与工具输出均生效，试运行可查看逐步返回的内容。
跟随主 API 使用酒馆 `generateRaw`，仍是非流式文本模式，不支持此处的工具参数。

在副 API 渠道编辑框选择请求方式：

- **酒馆转发**：默认。工具配置通过 custom 源透传。
- **浏览器直连**：浏览器直接向该渠道的 `/chat/completions` 或 `/models` 发请求，只发送 API 凭证，不携带酒馆 Cookie 或 CSRF 请求头。不绕过服务端的 CORS 或浏览器 HTTPS 限制。不可连接时改回酒馆转发。

请求方式是柏宝绘的私有渠道偏好，不改变柏宝书共享的 API 渠道结构，也不随预设导出。
DSH 持久会话支持仅调整书写规范的预设；暂不能与启用的非空画面条目、工具输出或浏览器直连组合，会在请求前给出明确错误。

## 本地检查与试运行

漫画预设可将“漫画文字”设为“必须有叙事文字”。旧预设默认“按剧情安排”，行为不变。此选项仅在漫画 Layout 模式生效，并随预设导入、导出。

启用后每页须提供至少一个非空的对白、心理、旁白或消息 text 项，caption 明确 `spoken by` / `speech bubble`、`thought bubble`、`narration box` 或 `chat message box` / `text message box` 等类型，且使用合法字区。仅有拟声或招牌不算叙事文字。预设要求先选择有原文依据的文字再安排分镜，不允许通过隐藏关键消息来规避文字。

试运行和正式自动配图使用同一检查。首次缺字或文字布局无效时最多补正一次，历史标记“文字补正 1/1”；仍失败则停止，不提交生图，也不继续一般自动重试。补正会产生一次副 API 请求费用，不产生云端生图费用。没有生成任何页面时不强制创造页面或台词。

程序检查的是文字字段、类型描述和布局合法性，不代表已经验证文字忠于原文，更不保证图像模型最终逐字准确。需实际出图检查。编辑内容后旧预览失效，须重新本地检查。

漫画预设可将“漫画表现”设为“生动叙事 · 不强制出框”（`mangaComposition: "expressive"`）。保留原字段值兼容旧预设；从 0.3.16 起，它不再代表强制出框。`auto` 仍按预设安排。

- 按短事件、情绪落点与文字容量组织整页，强调镜头衔接、画面主次、人物状态和场景连续性，不用独立摆拍或无关空景填格。
- 版式清单只发送一份，不再重复一整份跨框能力表。参考之前最多四张 AI 配图的版式，不随机轮换，不禁止合理复用。
- 出框、嵌入与重叠是可选手法；没有跨框区域或选择完整格内人物，不再触发拒绝或补正。版式、尺寸、槽位与文字有效性仍须校验。
- 无效构图与文字共用最多一次补正请求，不是各重试一次。记录按首次失败类型标记“构图补正 1/1”或“文字补正 1/1”。
- 最终编译为使用中的跨框人物补充前景遮挡、越线方向，并为各格文字补充顺序。编号和布局说明不会作为可见文字输出。

漫画创作偏好集中在预设。高级设置中的旧版“版式选择说明”仅为兼容保留，仍按原行为附加；升级不会清空用户自定义内容。个人预设中自行写入的强制出框要求也不会被插件擅自删除。

`examples/manga/` 提供三套竖版 JSON（默认 1664×2496）：对谈与落点、场景与双重反应、人物与消息连拍。它们由 `src/manga/editorialLayouts.ts` 生成，不自动安装、不覆盖旧模板；在“漫画版式 → 新增版式（JSON）”中将完整 JSON 替换示例后保存。当前没有版式文件上传按钮。

其中“人物与消息连拍”标记为实验：实图可能合并右侧分界线，不建议作为稳定出框的默认选择。

构图检查只验计划与几何，不是图像识别：模型仍可能忽略侧向越线、交换字区或产生错字。必须检查实际图片，不能将结构验收通过等同于最终漫画质量达标。

“本地检查”不调用副 API、不请求生图，检查条目和变量，并展开准备发送的消息。
留空测试正文使用当前聊天最后一条 AI 回复；填写文本则创建隔离的测试场景。生图世界书测试不推进私有计时状态。

“测试副 API”是**计费请求**，只请求并验证配图计划，不请求 RunningHub/ComfyUI/NAI、不写正文、不保存角色变化。
它使用同一消息构造与响应解析逻辑，但不是完整的出图质量测试。普通渠道可取消网络请求；跟随主 API 时取消只阻止使用结果，宿主内部请求可能仍在进行。
兼容性提醒并不代表某个第三方模型已经实测成功，应使用自己的渠道做一次试运行。

副 API 渠道中的“连通性测试”只发送一句简短文本，不加载配图预设、世界书或工具定义。若这里也返回 AI Studio 的 Build/Playground 或 `PROXY_GENERATION_DISABLED` 错误，应检查上游代理的模型路由和参数支持，修改配图预设或 RunningHub 工作流无法修复代理端限制。

## 导入格式

支持以下明确格式，不猜测任意文件含义：

1. 柏宝绘原生格式，固定 `format` 和 `version`。当前导出 v2，同时兼容 v1；导入旧格式不会继承本机旧全局自定义文本。
2. `[{ "role": "system", "content": "..." }]` 消息数组，或 `{ "messages": [...] }`。
3. 包含 `entries` 的原生条目对象。
4. 智绘姬请求类型档案：只提取 `image_gen.context_profile` 指向的正文配图条目。
5. 智绘姬上下文预设名称映射，例如 `{ "预设名": { "entries": [...] } }`。

包含自定义 `tools` / `functions` 或指定工具调用协议的完整 API 请求不是消息预设。导入器会拒绝这种文件，不会静默丢弃工具后假装兼容。仅转换条目不代表复现原插件的请求包装、输出提取和执行环境。

智绘姬转换保留条目顺序、名称、启用状态、消息角色、主/附加关键词。提供部分常用中文变量别名。
**不保证原文件开箱即用**：原来的 XML 输出、挂载正则、`display_stream`、`【ToolCall引导】`、专属服装库和角色占位符调用并非柏宝绘协议。
工具引导块或未提供变量会明确阻止请求；需要在编辑器修改或停用对应条目。旧 XML 指令应删除，最终始终遵守柏宝绘的 JSON 契约。没有复制外部项目的脚本执行、越权宏或其他任务引擎。

原生文件示例：

```json
{
  "format": "baibai_image_prompt_preset",
  "version": 2,
  "preset": {
    "name": "清晰叙事",
    "description": "主体明确、人物一致",
    "output": "text",
    "rules": {
      "comfySpec": { "mode": "builtin", "text": "" },
      "comfyThinking": { "mode": "builtin", "text": "" },
      "jailbreak": { "mode": "off", "text": "" }
    },
    "variables": { "画面偏好": "优先明确主体与自然光影" },
    "entries": [
      {
        "name": "基本要求",
        "enabled": true,
        "role": "system",
        "content": "忠于正文，保持人物外貌和场景连续。{{画面偏好}}",
        "trigger": "always",
        "keywords": "",
        "andKeywords": ""
      }
    ]
  }
}
```

ID 由导入器重新生成。单文件不超过 2 MB、单份最多 2000 条目，预设库不超过 10 MB。
导出不包含渠道、API 密钥或其他任务配置，但**你自己写进提示词或变量的私人文本会随预设导出**，分享前请检查。

## 0.3.17: Input Inspection And Waiting Feedback

Local preset checks display the actual cleaned target paragraphs, character
counts and whether the selected preset is active. A fully removed story is
blocked before testing the model. Local checking does not send a model request.

During streaming requests, history distinguishes response headers, received
reasoning, received plan content and plan validation. Counters are characters,
not tokens. Explicit permanent HTTP rejections stop automatic retries; temporary
failures retain the configured retry budget. None of these changes replaces
image-quality verification.

## 0.3.20: Request Evidence And Compatibility Boundaries

请求历史与本地预览显示每段消息的来源：预设条目、书写规范、插件提交协议、检查指导、角色资料或世界书。来源只在本地展示，发送时仍只有标准 role/content。历史按发送前实际字符数计数，不再把截断留存内容的估算当成整段长度。

每次独立副 API 请求还保留一份白名单参数摘要：提交方式、工具名、输出上限、温度、流式与思考强度。不记录 API 密钥、请求头或工具说明；酒馆转发时摘要描述插件交给酒馆的请求，不保证第三方脚本或上游没有再次改写。跟随主 API 的宿主黑盒路径不推测参数。

HTTP 200 只表示收到接口响应。上游 `content_filter` 单独报告并停止一般自动重试；`length` 报告输出截断；仅有原生 reasoning 而没有最终正文时明确报告“仅返回思考”，不把推理草稿当作成功配图计划。流式失败、超时或取消时也刷新已收到的最后进度，避免仍显示过时计数。
